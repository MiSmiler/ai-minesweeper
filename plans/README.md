# plans

**临时文档**：开发过程中的计划、决策与关注点。这里的东西不是产品的一部分——一组工作落地之后，它就没有读者了。

## 结构

- **一个目录 = 一个分支**：目录名对应它服务的那条分支，例如 `plans/sessionbox-message-list/` 服务 `feat/sessionbox-message-list`。
- 一个目录里可以有很多 md，**每个 md 是一个关注点**，它的改动刚好适配一个 commit。
- 关注点按依赖顺序编号，编号写在文件名开头：默认就是 `01`、`02`、`03`……。
- **插队才用字母**：讨论中冒出一件必须排在某一项之前的事，就在那个位置上展开——`01a`、`01b`、`01c`——后面的编号一律不动。重编号会牵动每篇里按编号写的交叉引用，不值得为编号的整齐付这个代价。（`sessionbox-message-list/` 就是一次：原本只有 `01`，讨论后发现两件事要先落，于是成了 `01a`、`01b`、`01c`。）
- `00-*.md` 是例外：它是这一组的**共享文档**（模型、契约、术语、同步方式），本身不落 commit，只被其余各篇引用。
- 一组关注点全部落地后，这个目录就删掉。

## 一篇关注点里写什么

目标、已定决定（连同取舍的理由）、未定决定（以及留给谁定）、实现须知、完成判据、涉及文件。判据写成可验证的东西；"为什么这样"和"被否掉的选项"跟决定写在一起，免得后来的人重新发明一遍。

## 不放在这里的东西

- 长期决策去 `docs/adr/`（或该 context 自己的 `crates/<context>/docs/adr/`），领域词汇去 `CONTEXT.md`——它们与实现同一个 commit。**这里不是它们的家。**
- 文档里引用的 `file:line` 是写作当天的代码位置，会漂移；以代码为准。
