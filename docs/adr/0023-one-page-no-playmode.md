# One page: no PlayMode, the AI panel sits beside the Board

ADR-0012 made PlayModes exclusive — a Game has exactly one at a time, and switching one for the other abandons the current Game and starts a fresh one. ADR-0019 named the two members, `HumanPlay` and `AiPlay`. The product no longer wants that split. There is one Game, and `HumanPlayer` and `AiPlayer` are two parties who can play it (`HumanPlayer` still the only one with hands on the mouse), not two pages to choose between. The tab strip forced the choice before the user could know which they wanted, and the exclusivity made the wrong choice expensive: picking the other tab threw the Game away — a real cost paid for a distinction the UI did not need.

The page is now a single layout: the Board on the left, an AI column on the right holding the dashboard above the SessionBox. There is no PlayMode, no mode switcher, no `?mode=` query parameter, and no mode-switch discard confirm. The `app/` composition layer loses its reason to exist: `mode.ts` and `humanPlayMode.ts` are deleted and the one remaining composition (`layout.ts`) is mounted directly by `main.ts`, which keeps only the `beforeunload` guard (the browser's only sanctioned way to warn that a refresh would discard a live AI Session — a custom confirm cannot block unload).

The SessionBox is hidden until a Session exists, keyed off the existing three-valued `sessionState`: visible exactly when `sessionState !== "none"`. That single predicate already has the right lifecycle — `begin()` moves `none` → `unused`, the first Send moves it to `used`, and New Game (`machine.end()`) drops it back to `none`, hiding the box and clearing its content. While hidden the box does not occupy space (`display: none`), so the column holds only the dashboard; when shown, the column fills the viewport height, the dashboard takes its natural height, and the box absorbs the rest so the stream scrolls internally rather than stretching the page (the bound issue #119 asked for).

What survives from ADR-0012/0019: the terms `HumanPlayer` and `AiPlayer` (who plays, who drives — they do not name a screen location), `SessionBox`, the per-mode-independent `createGameArea` seam, and the dashboard's guards. What goes: the PlayMode concept altogether, the `Composition` concept (one layout, one `LayoutHandle`), and the rules that switching abandons the Game.

Considered: keeping the tabs but sharing one Game across them (rejected — a shared Board under a tab strip is a mode switch in all but name, and it keeps the vocabulary that made the code claim a switch loses the Game); keeping `HumanPlay` as the default mode with the AI panel collapsed (rejected — a collapsed panel is a toggle, and a toggle is what makes the distinction a mode); hiding the SessionBox behind a generic disclosure instead of the Session (rejected — the box exists to show a Session, so the Session's own presence is the honest trigger).
