# The Session log holds more than the model sees

> Amended by ADR-0027: a provider failure is a failed Run; the Send's own
> failure is the one that never reached the Provider.

A Session's history is the agent's own `Message` — an append-only log of what happened — and the provider's `Message`, the shape an OpenAI-compatible request body is made of, is a lossy projection of it, built when a `ChatRequest` is assembled. Two facts forced the split. An Interrupt had nowhere to live: the caller's act of stopping a reply is a fact about the Session, and with one shared type it could only be recorded as the absence of a reply, outside the log. And a log typed as one wire's shape leaks that wire's vocabulary outward: `ContentBlock`'s hand-written serde writes a vendor's downscaling instruction (`detail: "low"`) into the JSON the frontend reads, where it can only be ignored.

An Interrupt now appends `{"role":"assistant","content":"","interrupt":true}` to the log, and the projection drops it. The provider is sent what the model needs to read, and "the caller stopped here" is not part of that. The marker carries nothing else on purpose: reasoning and content that had already streamed are discarded, because an interrupted reply is not a Reply — and a marker holding them would be one `filter_map` mistake away from feeding half a reply back into the model's context.

Considered options: one `Message`, with `interrupt` added to the provider's type (rejected — it puts a fact that is never sent into the provider's contract, and accepts that one wire's shape is our shape); an enum carrying the reason (`Interrupted` / `Failed` / `Unread`) in place of the `bool` (rejected — the other two endings are not entries this log should carry: a provider failure is a failed Run, reported beside the list rather than in it, and a stream that ends without `Done` lands nothing at all, so re-reading the log recovers it); a marker carrying the text that had already streamed (rejected — half a reply is not a Reply, and carrying it is a liability in the projection).

Consequences: the log is the Session's truth, so building a request is a filter-map over it rather than a total function — every place that assembles a `ChatRequest` must apply it, and `Agent::send` is the only one today. The frontend reads the log (`GET /ai/messages`), so the wire carries `ContentBlock`'s `detail` field until the image detail level becomes a Send parameter. ADR-0024's "without a reply" is amended rather than reversed: nothing lands as a Reply, and an Interrupt lands a marker. The glossary narrows with it — a Session's log may hold an entry that is not a Reply, and a Reply is not the only assistant-shaped message.
