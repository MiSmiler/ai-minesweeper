# Gesture machine as an explicit state machine

The frontend gesture machine is an explicit three-phase state machine — idle / pressing / armed — where the Left press is a preview gesture (issue #38: pressing shows a Press Preview that follows the pointer, releasing Reveals the Cell under the pointer, leaving the Board cancels the press) and the Chord gesture Arms when both presses land on Revealed Cells, shows the Chord Preview over Revealed numeric Cells, and solves on Left release. Each handled event reports its phase change (`phaseChange`: pressed / released / armed / disarmed) and its in-phase effects (`effects`: flag / reveal / chord / press-preview-* / chord-preview-*) on separate channels, so one event can report several observables — Arming logs both `armed` and `chord-preview-set`, blur both `disarmed` and `chord-preview-cleared` (issue #45) — instead of a single transition slot where one overwrote the other.

The phase machine replaces a boolean-flag event handler. The flags became unmaintainable once one event could change several things at once (Arm + Preview) and the press gesture (issue #38) added a second preview lifecycle; the phases make every transition explicit and give each phase a single, readable decision function. A flat transition list and structured orthogonal fields were rejected: a list hides which entries are state changes and which are effects, and orthogonal fields (armed? preview change? action?) scatter the same information across ad-hoc booleans again. The reporting was later split from the per-phase logic: each phase handler returns a flat decision — the next state plus the deltas (`action`, `phaseChange`, `effects`) — and the machine commits the next state and projects the renderable output in one place, so a branch body only expresses what changed and the output cannot drift from the committed state.

Gesture rules that look surprising and are deliberate: Arming requires both presses to land on Revealed Cells (any Revealed content, not only numeric — a Revealed non-numeric Cell still qualifies, though it shows no Preview); a Flag fires only on Right-down with no Left held, so an arming Right-down flags nothing; releasing Right does not disarm an armed Chord; a press cancelled by leaving the Board drops its Arm eligibility; and leaving the Board while armed terminally clears the Chord Preview — it does not return on re-entry until the gesture re-arms, mirroring the Press Preview. The machine stays pure — it reports outputs, and the caller renders and logs them.

The machine has an enable gate instead of a synthetic control event: the caller closes it (`setEnabled(false)`) once the game is Won or Lost — which cancels any in-progress gesture, closing the race where a press lands before the ending response arrives (issue #50) — and reopens it on a new game; a closed machine ignores every event. The caller drives the gate from the game state on every response, so it cannot drift. The machine reports `boardPressed` — whether a press is held over the Board — so the caller renders the Smiley Button's surprise face from the machine's output, leaving only the state-driven face (🙂/😎/😭) to the top-bar renderer. The gate is just another input, so the purity claim still holds: the machine stays pure — no I/O — with the phase state and the gate as its only state.
