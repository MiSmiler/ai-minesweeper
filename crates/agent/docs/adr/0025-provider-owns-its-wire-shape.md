# The provider owns its wire shape

`agent::protocol` claimed to be a neutral middle layer — its module doc called its contents "Provider-agnostic value types ... exchanged with any provider" — while holding exactly one vendor family's shape. `ChatRequest` serialized straight into the body DeepSeek receives, `ThinkingToggle` documented itself as "the wire shape of DeepSeek's `thinking` parameter", and `ContentBlock`'s hand-written serde was the OpenAI nesting. Reading a type name told you nothing about who defines the shape or who may change it, so every new field started with the question "is this part of the provider's contract?".

The types now sit on the side that can extend them: the seam's own vocabulary — `StreamChunk` / `ProviderError` / `ProviderErrorKind`, the words in `Provider::stream_chat`'s signature that any vendor must be able to say — in `provider/mod.rs`; the request-side shapes (`ChatRequest`, `Message`, `ContentBlock`, `ToolCall`, `ToolDecl`, `ReasoningEffort`, `ThinkingMode`, `ThinkingToggle`) in `provider/openai_api.rs`, named after the API family they belong to. `protocol` is deleted with its module. This is a move only: no name, field, derive or serde attribute changed, and the crate root re-exports the same names as before.

Considered options: keeping `protocol` as a neutral middle layer (rejected — it was never neutral, and its neutrality was the cost: "provider's contract or ours?" had to be re-answered for every field, with the answer always "provider", since the shape is the API family's); naming the new module `wire.rs` or `chat.rs` (rejected — the name would hide which API family the shapes belong to; a vendor that is not OpenAI-compatible gets `somevendor_api.rs` beside it instead of a share of one "neutral" file); renaming the provider's `Message` to `ChatMessage` in the same step (rejected — a rename would blur what this decision did, which is move code, and separating the Session's message from the wire message is its own decision to be argued and reviewed on its own).

Consequences: the `Provider` seam is on record as speaking the OpenAI-compatible request shape, so a vendor that is not OpenAI-compatible translates that shape into its own wire inside its implementation rather than the seam pretending to be vendor-neutral. Inside the crate, the layering rule the crate root states — one internal edge, `agent → provider` — becomes readable off a type's module: a type in `provider` is the provider's to define, a type in `agent` is ours. `ThinkingLevel` stays in the agent layer for that reason: it is the caller's vocabulary, mapped onto `reasoning_effort` / `thinking` at the seam. No consumer outside the crate sees the move.
