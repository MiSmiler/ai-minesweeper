# A Send triggers, and a Run executes

`Agent::send` answered with `Result<Stream<Item = Result<StreamChunk, SendError>>, SendError>`: one type for two positions. `NoSession` and `Busy` were refusals before the exchange, `Provider` was the Provider failing either at delivery or mid-stream, and the caller's own Interrupt sat in the error slot — while the wire had always carried it as an event. Which variant could appear where was a comment on the type, "The variant set is position-restricted ... The compiler cannot enforce this", and the transport hand-wrote both halves of the enforcement: an `unreachable!("a refusal cannot be a reply-stream item")` arm, and an `internal error: a Send reported an interrupt before it started` branch.

The vocabulary was doing the same thing: **Send** named both the trigger and the whole span. The words now split. A **Send** is the trigger — the call, its admission, up to the point the caller's messages land. A **Run** is what the Send starts: from those messages landing to the stream ending, deltas streaming on it, the reply landing on `Done`, the caller's Interrupt stopping it. `send` returns `Result<Stream<Item = Result<RunEvent, RunError>>, SendError>`: `SendError` holds `NoSession`, `Busy` and the delivery-time `Provider` failure — the Run never began; `RunError` holds the mid-stream `Provider` failure; and the caller's Interrupt leaves the error slot for `RunEvent::Interrupted`. The Run also owns its event type instead of borrowing the Provider's `StreamChunk`, which is the Provider seam's cell and never carried an `Interrupted`.

The cut is by position, not by cause: a Provider failure is the same `ProviderError` travelling intact on both sides. What the two types buy is exactly the contract the comment could only assert — `NoSession` / `Busy` are unreachable on the stream, `Interrupted` is unreachable in `send`'s return value, and both hand-written enforcement sites disappear with the compiler doing the work.

Considered options: keeping one type and the comment (rejected — the comment *was* the enforcement, and every consumer still had to branch on position by hand); cutting the failure vocabulary by cause instead of by position, so that the stream reported Interrupts and Provider failures in one bucket (rejected — it is the lossy refraction ADR-0022 removed: one 429 would be two facts); folding Interrupted into the Provider failure (rejected — an Interrupt is an act, not a cause; ADR-0026 and the glossary say so).

Consequences: an aggregate that spans both positions — `complete_once`, `run_loop` — folds `RunError` back into `SendError` (`Provider` is the one cause both carry) and answers an interrupted Run with "no reply" rather than an error, because the marker, not a Reply, is what landed. The frontend takes the same two names (`RunEvent` / `RunFailure`) into `frontend/src/agent/run.ts`, but keeps one failure type: a refusal and a Provider failure arrive by two paths (`onFailure` and a `provider_error` event) into one field, and TypeScript cannot enforce a position restriction that Rust's types carry. ADR-0022's core stands — one cause type, one record, no refraction — and only its closing sentence moves: the contract it documented on the type is now the types themselves. ADR-0021, 0024 and 0026 stop using "Send" for the whole span.
