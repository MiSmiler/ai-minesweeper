# One failure vocabulary for a Send

> Amended by ADR-0027: the position contract this ADR could only document on
> the type is now two types instead — `SendError` for the Send and `RunError`
> for the Run. The one cause type and the one record of why an exchange
> produced no reply stand.

`SendError` was cut by pipeline position rather than by fact: admission refusals (`UnknownSession`, `Busy`), the policy check (`ModeMismatch`), Load failures and the provider's own failure all arrived in one type, while a mid-stream failure arrived in a second vocabulary — `InterruptReason` — whose buckets were a lossy restatement of `ProviderError`. The agent now has one cause type (`ProviderError`, travelling intact from the Prepare position into the stream) and one record of why a Send produced no Turn: `NoSession`, `Busy`, `Interrupted`, `Provider(ProviderError)`. `AgentError` is deleted with it — Load fails with a `ProviderError`, and "no provider" is a Config one at the source instead of a variant the transport translates back into a `ProviderError` by hand. Only the caller's own act is an **Interrupt**; a provider failing mid-stream is a `Provider` failure.

Considered options: keeping the two types and their two vocabularies (rejected — the same 429 is a `ProviderError` at Prepare and a `RateLimit` mid-stream, so a consumer branches twice on one fact); taking ADR-0014's deferred direction and merging the two-bucket `kind` into the finer `InterruptReason` taxonomy (rejected — the finer side is the lossy one: `SseState` only ever emits `{Upstream, code: None}`, so a mid-stream 429 or 5xx already collapses to `Timeout`, and the frontend never consumed the buckets — it prints the raw reason while classifying alerts from `kind` / `code`).

Consequences: the player-facing reason strings (`rate_limit`, `timeout`, `upstream_error`, ...) become a projection of `ProviderError` owned by the transport, not agent vocabulary. `NoProvider` loses its own status path: the app keeps mapping a config error with no code to 503, or accepts the 502 fallback. ADR-0014's mid-stream refraction, and the `Config -> Unknown` contract it carried, is removed; the Load / Prepare argument of that record stands. The one contract the compiler cannot enforce — `NoSession` and `Busy` appear only in `send`'s return value, `Interrupted` only as a stream item, `Provider` in both — is documented on the type. That contract is no longer a comment: `SendError` (`NoSession`, `Busy`, the delivery-time `Provider`) is `send`'s return value and `RunError` (`Provider`) is the Run's stream, so the position a failure can arrive in is the type it arrives as (ADR-0027).
